# T7: Blocks shell model (one input, command blocks)

- **Status:** implemented (zsh verified in the app; bash by test; fish untested, not installed here)
- **Priority / phase:** P1 · phase 3 (follows the user's 2026-10-03 feedback "we have two inputs")
- **PRD refs:** T1, T3, T4; "fast, modern terminal feel"
- **Related:** [T3](T3-shell-integration.md) (prompt marks), [T4](T4-command-blocks.md), [T6](T6-input-editor.md) (the editor)

## Summary

In shell tabs, the input editor (T6) is the only input. The shell's own prompt is blanked while the editor is active, so the terminal shows only commands and their output, grouped into blocks. Each block shows its exit status and duration. A per-tab **Classic** switch brings back the shell's own prompt and plain terminal typing.

## Behaviour and acceptance criteria

- [x] **Blank prompt:** with shell integration (zsh, bash, fish), the shell draws an empty prompt (`PS1`, `RPROMPT`/right prompt and `PS2` empty) unless the terminal is in classic mode.
  - Blanking runs at the end of the prompt hooks, so prompts that frameworks rebuild before every prompt (Powerlevel10k, Starship, oh-my-zsh themes) are blanked too.
  - The user's prompt is remembered and restored when switching to classic mode.
- [x] **Classic mode:**
  - Per terminal, switched from the editor's chip row ("Classic") and back from a small "Blocks" pill in classic mode.
  - `terminal.set_classic {id, classic}` records the choice in a marker file the shell checks before each prompt (`$JAUNT_CLASSIC_FILE`), updates `TerminalInfo.classic` and emits `terminal.updated`.
  - The frontend sends an empty Enter when the shell is at a prompt, so the new prompt mode shows immediately.
  - New shells start in Blocks mode unless the "Classic shell prompt" setting is on (`terminal.create {classic: true}`).
  - In classic mode the editor never shows.
  - The choice is not kept when a daemon restart re-creates the shell (it starts in the default mode). A live upgrade keeps it.
- [x] **Command blocks:**
  - A thin separator above each command.
  - A chip at the right end of the command line: `✓ 1.2s`, or `✗ 1 · 300ms` for a failing exit code, or a spinner while running. *Replaced by the block header in [T8](T8-block-styling.md).*
  - Duration is measured in the app from the `C` mark to the `D` mark.
  - Screen snapshots carry no prompt marks, so output from before the app attached has no blocks. The first command after attaching opens its block at the `C` mark, on the line above the cursor.
- [x] **Cursor:** the terminal cursor is hidden while the editor is active.
- [x] Agent, run and setup terminals, structured chats and shells without integration are unchanged.

## Protocol

- `TerminalInfo.classic: bool`.
- `TerminalCreate.classic: bool` (default false).
- `terminal.set_classic {id, classic}` returns the updated `TerminalInfo`.
- Marker files live in `~/.jaunt/run/prompt/<terminal id>`. They are removed when the terminal is removed.

## Security

The marker path is generated by the daemon from the terminal id; no client-supplied paths.

## Test plan

- Rust:
  - zsh and bash with a user prompt `USERPROMPT>`: the prompt is not printed in Blocks mode, and it is printed after `terminal.set_classic` and an empty Enter.
  - `set_classic` writes and removes the marker file.
- TS: block chip formatting (`✓ 1.2s`, `✗ 1 · 300ms`).
- In the app:
  - A fresh shell shows no prompt and the editor.
  - Running `ls` and `false` shows two blocks with chips.
  - Classic shows the user's prompt; the Blocks pill brings it back.
  - `vim` still hides the editor.

## Out of scope

- Collapsing blocks, and per-block actions beyond the existing copy commands.
- Rendering the user's prompt segments as chips.

## Verification (2026-10-03)

In the app, in a fresh zsh in a test session, with the user's own zsh configuration:
- No shell prompt appeared, the editor was the only input and the terminal cursor was hidden.
- `ls`, `false` and `sleep 3` showed separators and right-hand chips: `…` while running, then `✗ 1 · 0ms` and `✓ 3.0s`.
- Classic showed the user's own prompt with the cursor and the "Blocks" pill; the pill switched back.
- `vi` hid the editor and `:q` brought it back.
- The first command after an app restart got its block.

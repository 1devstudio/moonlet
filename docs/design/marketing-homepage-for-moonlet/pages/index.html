One mesh of machines

The machines you own, working as one.

Your Macs, a Linux VPS and your phone pair once over your Tailscale tailnet. There are no SSH keys and no port forwarding. One of them is always on and keeps a copy of everything.

The same workspaces everywhere

Workspaces, sections, design systems and designs are on every machine. A change made on one shows up on the others within seconds.

Every session has a copy

The machine running an agent checkpoints the worktree and the transcript after every tool call. Nothing lives only on the laptop.

Sessions follow you

Close the lid and the central host continues. Type on another Mac and the session moves there. Move to a machine pins it there when you want it to stay put.

Switch to your phone in one step

Scan a code to pair. The iPhone app lists every session wherever it runs, answers prompts and plans, and opens chat, terminal, changes and PR.

What git ignores comes along

.env files and the patterns you list are copied between machines. Sign-ins like gh auth login open where you are.

Heavy work goes to free machines

Test suites run on the least busy machine, or on a cloud machine made for the job and removed when idle. Follow each run in Jobs.

Hosts and workers

Heavy work goes where there is room.

Hosts run your agents. Workers lend their CPU. When an agent runs a command you marked as heavy, moonlet sends it to the least busy machine, and makes a cloud worker when every machine is full.

Hosts

Your MacBook, a Mac mini, a Linux VPS. Each keeps the whole account and can run sessions.

Workers

Cloud machines on Hetzner or Google Cloud, made for heavy commands and billed by your own provider.

Jobs

Every routed command is a job in the session's Jobs tab: where it ran, its output and what came back.

Design systems and prototypes

Prototype the screen before the agent writes the code.

An agent turns your project's code into a design system. Then you sketch new screens on it in minutes, without running the project.

  1. 1
    A design system from your code

    Tokens, type, spacing and one card per component with every variant, in plain HTML and CSS. Any stack works, and a sync only redoes the cards whose source changed.

  2. 2
    Design mode ⌃⌘D

    Describe a screen and an agent builds it live on a canvas. Chat, pin comments on elements, or move and restyle them yourself. Every turn is a snapshot.

  3. 3
    Build it

    Start a session with the design attached. The prototype, its spec and the code ship in the same pull request.

Start from a task

Pick an issue. The session starts from it.

moonlet shows your tracker's board beside the sessions and pull requests working on each issue, and keeps the tracker in step as the work moves.

    The issue's title and description become the first message, with the project picked and a branch named after the issue.

  2. 2

    The issue moves when the session starts, when its PR opens and when it merges. A task whose state no longer matches its work says so, with a one-click fix.

Free and open source

Free, open source, and yours.

moonlet costs nothing and its source is on GitHub. It runs on machines you own, with the agents and logins you already have.

Free to use

No price, no plan and no seats. Cloud machines, when you use them, are billed by your own provider.

MIT or Apache-2.0

Pick either license. Read the code, build it yourself, fork it and change it.

Your machines, your agents

Sessions run on your Macs and Linux boxes, and they talk over your own tailnet. Claude Code and Codex use your own logins.

Built in the open

Every feature has a public spec, and the big decisions are written down as ADRs. Bug reports, ideas and pull requests are welcome.
